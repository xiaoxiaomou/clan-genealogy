# 族谱系统 · 权限说明报告

> 生成时间：2026-11-14 · 依据：`app/utils/decorators.py` + 全部路由装饰器静态审计（共 199 个接口）
> 范围：后端接口权限 + 前端页面可见性。不含数据内容层面的业务规则。

---

## 一、权限模型总览

系统采用**两层权限**模型：

```
系统层：User.is_admin（系统管理员）
家族层：FamilyMember.role → owner(4) > admin(3) > editor(2) > viewer(1)
访客层：未登录用户（仅对 is_public 公开族谱的 viewer 级接口可见）
```

三条基本规则（`app/utils/decorators.py`）：

1. **系统管理员自动通过一切家族权限检查**——`family_permission_required` 中显式写着"管理员自动通过权限检查"，`is_admin` 用户不受家族角色限制。
2. **家族角色按层级继承**——owner 拥有 admin 及以下的全部能力，依次类推。
3. **公开族谱例外**——`family.is_public = true` 时，未登录访客可直接访问该族谱的 viewer 级接口（只读类）。

接口权限分布统计（共 199 个）：

| 门槛 | 接口数 |
|---|---|
| viewer（家族只读） | 68 |
| editor（家族编辑） | 46 |
| 登录即可（与家族无关） | 29 |
| 家族 admin | 31 |
| 系统管理员 | 24 |
| 家族 owner | 1 |

## 二、系统管理员（admin/admin123）

### 能做

- **用户管理**：查看全部用户、审核注册（批准/拒绝）、禁用/启用账号
- **系统配置**：查看/修改/批量修改/重置/初始化平台配置项（config）
- **数据维护**（本次新增）：创建/下载/删除数据库备份、完整性诊察、孤儿文件清理、全站家族列表
- **审计日志**：查看与导出平台级审计日志（config/admin/audit-logs）
- **创建家族**：`POST /family` 明确标注「创建族谱（仅管理员）」——**系统管理员是唯一能新建家族的身份**，创建后指派 owner
- **一切家族权限**：进入任何家族，执行 owner 级及以下全部操作（绕过家族角色检查）

### 不能做 / 边界

- 无"降级为普通用户后仍保留"的概念——权限完全由 `is_admin` 字段决定，撤掉即失去全部系统权限
- 系统管理员**也在审计日志的记录范围内**：修改配置、建备份等操作同样写入 audit_logs
- 禁用自己：`disable` 接口未做自我保护校验（管理员可禁用任意用户，含自己）——低风险但值得知晓

## 三、普通账号（未加入任何家族）

### 能做（29 个接口）

- 注册（**注册后进入待审核状态，需系统管理员批准才能登录使用**）
- 登录 / 刷新令牌 / 忘记密码 / 重置密码 / 修改密码
- 查看与修改**自己的资料**（`auth/me`）、上传**自己的头像**
- 查看公开配置、全局搜索、最近搜索
- 查看通知、标记已读、清空未读
- 通过**邀请链接加入家族**（`POST /join`）或凭分享令牌查看公开分享页
- 查看示例数据集

### 不能做

- ❌ **创建家族**（`POST /family` 为系统管理员专属，见「审计发现」第 1 条）
- ❌ 查看 /admin 系列任何页面与接口
- ❌ 未被邀请/加入时访问任何家族数据（公开族谱的只读内容除外）
- ❌ 审核其他用户、修改系统配置、备份数据

## 四、家族内身份对照（owner / admin / editor / viewer）

加入家族后，按 `FamilyMember.role` 获得能力。数量为该级别的接口数。

### 家族 owner（所有者，1 个专属接口 + 全部下级能力）

- **删除整个家族**（唯一的 owner 专属接口，家族及其数据整体删除）
- 全部 admin 级能力（见下）

### 家族 admin（家族管理员，31 个接口）

- **家族设置**：修改家族名称/简介/籍贯等
- **成员管理**：批量删除成员、添加/移除家族用户、**分配与调整家族角色**、绑定/解绑用户与成员档案
- **房支管理**：房支的增改删、排序
- **世代规则**：字辈世代规则的增改删
- **删除类**：删除事件、相册、荣誉、历史事件、编辑历史批次
- **邀请**：生成/查看/删除邀请链接
- **分享链接**：创建/查看/删除公开分享页
- **族谱合并**：合并预览与执行
- **审计日志**：查看家族级审计日志与统计

### 家族 editor（编辑者，46 个接口）

- **成员**：新增/编辑/删除成员，批量编辑与排序，CSV/Excel 导入
- **谱系内容**：建立关系（父子/配偶/兄妹）、家族简介、文章、大事记、荣誉、历史事件
- **中式字段**：葬地、迁徙、适嫁（出嫁女子）录入与编辑
- **录入工具**：OCR 识别导入、GEDCOM 导入、快速建家庭（单人/多代）
- **相册**：上传照片、编辑相册信息
- **字辈**：字辈诗设置
- 导出：CSV/Excel 模板与成员导出、家族备份导出

### 家族 viewer（查看者，68 个接口）

- **只读**：成员列表、世系/亲缘计算、关系路径、相册、文章、大事记、荣誉、历史、房支、世代规则、理事会、纪念、祭日
- **可写仅限社区类**：族内聊天发消息、家族动态发帖/评论/点赞、家族活动报名登记
- ❌ 不能修改任何谱系数据、不能上传相册照片、不能导入导出

### 访客（未登录）

- 仅当族谱被设为**公开**时，可访问其 viewer 级只读接口（如分享出去的族谱页）
- 非公开族谱：一切接口 403

## 五、前端页面可见性

| 页面 | 系统管理员 | 家族 owner | 家族 admin | editor | viewer | 未加入 |
|---|---|---|---|---|---|---|
| 登录/注册/忘记密码 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

## 六、审计发现与处置（2026-11-14 已修复 ①②④）

1. ✅ **已修复**：创建家族原为系统管理员专属。现改为**任何登录用户可创建家族**，创建者自动成为 owner（`POST /family` → `@login_required`，服务层本就将创建者写为 owner）。管理员仍可创建并指派。已实测：普通用户建家族 → owner → 建相册/事件 → 删除，全链路通过。
2. ✅ **已修复**：相册/事件/GEDCOM 导入共 **10 条路由**存在双重门槛（`@admin_required` + 家族角色叠加），家族管理员/编辑者即使有角色也会被系统级门槛挡住（建相册、删事件、导 GEDCOM 全部 403）。已移除叠加的系统级门槛，统一按家族角色裁决（相册增改=editor、相册删=admin、事件增改=editor、事件删=admin、GEDCOM 导入=editor）。已实测：普通用户（owner）建相册/事件成功。
3. ⚠️ **保持现状**：公开族谱对未登录访客开放 viewer 级只读接口（分享场景需要）。在世成员隐私依赖成员级隐私开关，建议后续确认公开族谱的在世成员信息在返回前已脱敏。
4. ℹ️ **保持现状**：系统管理员绕过家族权限（平台方超级权限），全部操作已记录审计日志。

## 七、角色速查（一句话版）

| 身份 | 一句话 |
|---|---|
| 系统管理员 | 平台主人：管用户、管配置、管备份、建家族，进任何家族都是"超管" |
| 家族 owner | 这本谱的主人：唯一能删除整本谱的人 |
| 家族 admin | 谱局主事：管人、管角色、管房支、管邀请、看审计、管活动 |
| 家族 editor | 修谱笔杆：录人、修关系、写文章传志、批量导入 |
| 家族 viewer | 族人读者：只看 + 族内聊天发帖，不能改 |
| 未加入的登录用户 | 个人资料 + **自建家族（成为 owner）** + 等邀请 |
| 未登录访客 | 只能看被设为公开的族谱 |
